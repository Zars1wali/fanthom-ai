# Rebuild Fathom (AI Meeting Notetaker): Implementation Plan

> Audience: an AI coding agent + the human operator.
> Goal: ship a **deployed, seeded, polished** meeting-notetaker product in well under 24h, with `.agent-logs/` committed, a public repo, and a 5-minute walkthrough.

---

## 0. Read this first

### 0.1 What is judged
1. **Speed**: how much *working* product exists, and how fast.
2. **Product judgement**: what was built first, what was deliberately left out (and said out loud).
3. **UX/UI**: is it actually good to use?

So: a small number of flows that are **excellent and complete** beats a wide shallow clone. Everything must work on the live link, with seeded data, for a stranger who isn't signed in.

### 0.2 Who does what (agents cannot do everything)

| Human operator (you) | AI agent |
|---|---|
| Do the **8x agent capture setup** and confirm the capture test passes **before any code** | Everything in code, config, seed data, docs |
| Sign up to fathom.video (free plan), connect a calendar, record a real 2-minute self-call, take screenshots | Turn your notes/screenshots into a written "Product Teardown" (`docs/teardown.md`) |
| Provide API keys (Anthropic, DB, optional Deepgram/Google) | Wire env vars, never commit secrets |
| Deploy approval, DNS/domain if any | Deploy config, CI, smoke tests |
| Record the walkthrough (camera ON, <5 min) | Write the walkthrough script (`docs/walkthrough-script.md`) |

### 0.3 Hard gates (do not skip)
- [ ] **Gate 1**: Capture setup done at https://8x-internal.com/p/8x-agent-capture-setup and the **capture test passes**. No product code before this.
- [ ] **Gate 2**: `.agent-logs/` exists in the repo and is committed **incrementally** (every phase, not one lump at the end).
- [ ] **Gate 3**: Live URL opens in an incognito window with **no login required** (demo mode).
- [ ] **Gate 4**: Repo is public, contains `.agent-logs/`, README, seed data, no secrets.

### 0.4 Naming and legality
Do **not** copy Fathom's logo, name, copy or assets. Pick your own product name (e.g. "Tidewater", "Recall Notes", "Huddle"). Recreate *behaviours*, not branding.

## 1. Phase A: Understand the product (human-led, ~45–60 min)

Use Fathom properly. Capture screenshots into `docs/research/screens/`. The agent should read your notes and produce `docs/teardown.md`.

### Checklist of flows to walk end to end
1. Sign up on free plan → onboarding steps.
2. Connect Google/Outlook calendar → see upcoming meetings, per-meeting record toggles/settings (which calendars, internal vs external, who to share with).
3. Notetaker joins a real meeting (Zoom/Meet/Teams) → what does the participant see? (bot presence, consent notice, recording indicator).
4. **During the call**: highlight a moment (hotkey/button). Note how it's labelled and where it lands.
5. **After the call**: how long until it's ready; email/notification; meeting page layout.
6. **Playback ↔ transcript sync**: click a line, seek; auto-scroll while playing; speaker names; speed control; skip silence.
7. **AI summary**: sections, template switcher (e.g. general, sales, 1:1, standup…), regenerate, edit.
8. **Action items**: extraction, assignee, checkbox, jump to timestamp, copy/export.
9. **Highlights** list and creating a clip from them.
10. **Search across meetings** (keyword and "ask" style).
11. **Sharing**: share a clip/meeting with someone not on the call (link, permissions, what they see when not logged in).
12. **Big case**: an 8-person, 60-minute call. Observe: transcript length handling, speaker separation, chapters/topics, summary quality, performance/scroll.
13. Settings, integrations, team/library views, free-plan limits.

### Output of Phase A: `docs/teardown.md`
Sections: *What it does well · What's clunky · What's missing for long/multi-person calls · What I will build · What I will fake · What I will skip (and why)*.

## 2. Product decisions (pre-made, so the agent doesn't dither)

### 2.1 Positioning
"Fathom, but built for the **long, many-person call**": chaptered, speaker-aware, searchable, with summaries that don't fall apart at 60 minutes.

### 2.2 Scope: build order

**P0: must ship (core loop)**
1. **Meetings library** (seeded, 12–15 meetings): list with title, date, duration, attendees, summary snippet, status, filters (date, attendee, has action items).
2. **Meeting detail page**: player + synced transcript + AI summary + action items + highlights in one screen.
3. **Playback ↔ transcript sync**: click-to-seek, auto-follow, speaker colours, speed control.
4. **AI summary with template switcher** (≥4 templates: General, Sales discovery, 1:1, Standup/Project sync) generated by an LLM, cached per (meeting, template).
5. **Action items**: extracted, assignee + timestamp + done toggle, jump-to-moment.
6. **Highlights**: add at any timestamp (button + keyboard `H`), with optional note; appears in the list and on the timeline.
7. **Global search** across all meetings: transcript + summaries + action items; results show meeting, speaker, timestamp, snippet, click → deep-link to that moment. `⌘K` palette.
8. **Share a clip**: pick start/end (from highlight or range) → public link `/s/:token` viewable **without login** (clip player + transcript excerpt + summary snippet, revocable).
9. **The 8-person / 60-minute meeting**: flagship seeded meeting (see §6) with chapters, speaker talk-time, per-speaker filter, virtualised transcript, hierarchical summary.
10. **Demo mode auth**: "Try the demo" button → seeded workspace. No login wall.

**P1: high-value, do if P0 is solid**
11. **Live-meeting simulation (stubbed capture layer)**: "Join a meeting" → paste link → a simulated notetaker "joins", shows recording state, streams a scripted transcript live, lets you press *Highlight* mid-call, and on "end" produces a real meeting via the same pipeline.
12. **Calendar connect**: real Google Calendar OAuth (read-only) **or** stub with seeded upcoming events + per-event "Record" toggle. Pick one (see §7).
13. **Ask the meeting** (chat over one transcript, answers with timestamp citations) and **Ask across meetings**.
14. **Upload audio/transcript** → transcribe (Deepgram/AssemblyAI) → same pipeline (proves it's not fake end to end).

**P2: only if time remains**
15. Follow-up email draft, CRM sync stub, weekly digest, edit summary inline, dark mode, keyboard shortcut cheat-sheet.

**Explicitly OUT (say this in the walkthrough)**
Real meeting bot (Zoom/Meet/Teams), billing, team admin/roles/SSO, CRM integrations, mobile apps, real-time coaching, enterprise compliance. Rationale: capture is a solved commodity (Recall.ai etc.); value is in what happens *after* capture.

### 2.3 What is honest-stubbed
- **Capture layer**: stubbed. Say so in README + walkthrough. Architecture leaves a clean `CaptureProvider` interface so a real provider (Recall.ai) could drop in.
- **Audio**: seeded meetings use generated multi-voice TTS audio (or one looping neutral audio file) behind a `Player` abstraction; if no audio exists the player uses a **synthetic clock** so sync/scrub/highlights still work.

## 3. Tech stack

| Concern | Choice | Why |
|---|---|---|
| Framework | **Vite + React + TypeScript** (or Next.js) | High performance SPA, instant feedback, deep linking |
| Styling/UI | **CSS design system / tokens** | Clean, bespoke, rich typography and polish |
| Audio | HTML5 `<audio>` + synthetic clock | Resilient playback, seeking, highlights |
| Data | In-memory + LocalStorage client DB | Instant seed load, zero-latency filters |
